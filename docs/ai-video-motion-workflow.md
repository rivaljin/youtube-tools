## 핵심 원칙

### 1. 먼저 영상의 약속 하나를 정한다
한 편의 핵심 메시지와 도입·전개·마무리를 정한 뒤 코드를 작성한다.
기존 촬영 콘티는 CONTI.md를 참고하고, 이 문서는 후반 연출·모션그래픽 기준으로 사용한다.

### 2. 참고 영상은 정지화면뿐 아니라 움직임까지 측정한다
2초 간격 연락 시트는 전체 구성 파악용이다. 등장·퇴장·전환 분석에는 연속 프레임이 필요하다.
확인할 값:
- 화면 대비 글자와 제품의 크기, 위치, 여백
- 등장 시작·정착·퇴장 프레임
- 완전히 읽을 수 있는 유지 시간
- 이동 방향·회전·크기 변화와 가속·감속
- 다음 장면으로 이어지는 요소와 소리의 시점

측정값은 해당 참고 영상의 값이다. 예제의 13프레임 퇴장이나 44프레임 축소를 모든 영상에 고정하지 않는다.
한글은 영문과 글자 폭·조합·읽기 속도가 다르므로 별도로 조정한다.

### 3. 장면 사이에 요소의 움직임을 연결한다
매 장면 새 카드가 나타났다가 사라지는 패턴만 반복하지 않는다.
예: 하나의 제품 카드가 이동·회전·분리되면서 다음 비교 구도로 이어지고, 강조선이 다음 숫자의 밑줄로 이어지게 설계한다.
사진 줌과 문구 교체만으로 참고 영상 수준의 모션그래픽을 구현했다고 판단하지 않는다.
연속 변형은 유용한 원칙이며 모든 장면에서 강제할 공식은 아니다.

### 4. 시간은 하나의 표로 관리한다
FPS, 장면 길이, 시작 프레임, 자막과 효과음 시점을 데이터로 관리한다.
전체 길이는 장면 길이와 전환 겹침으로 계산한다.
장면 내부 프레임과 전체 영상 프레임을 구분하고, 보간은 유효 범위 밖에서 멈추게 한다.

### 5. 화면 규칙을 먼저 정한다
색상·폰트·크기·여백·모서리·강조 방식을 정한 다음 장면에 적용한다.
숫자는 실제 수치를 보간한 뒤 표시하고, 글자는 내용에 맞게 순차 등장·쓸려 나가기 등을 설계한다.
세로판은 가로판을 잘라내는 대신 글자 크기와 배치를 별도로 잡는다.

### 6. 소리도 장면별로 설계한다
음악, 큰 전환 효과음, 작은 동작 효과음을 구분한다.
모든 움직임에 소리를 붙이지 않는다. 중요한 순간에는 음악을 줄이거나 무음을 둔다.
효과음 파일의 시작과 실제 소리의 정점이 다를 수 있으므로 전환 시점과 맞춰 확인한다.
음원 파일 길이와 실질적으로 들리는 구간을 구분한다.

## 참고 코드 지도

원본 src/lib/:
- TypedLine.tsx: 글자별 등장 시간, 방향성 있는 퇴장. LetterLine과 letterSweep도 이 파일에 있다.
- GeometryWords.tsx: 하나의 도형이 축소·확장·분리되며 여러 문구를 이어가는 구현
- KineticCaption.tsx: 단어별 등장, 위치·흐림·투명도와 강조어
- MusicBed.tsx: 프레임별 음악 음량
- SfxCue.tsx: 특정 프레임에 효과음 시작
- DustField.tsx: 입자별 경로·깊이·주기가 다른 배경

원본 src/grammar/tokens.ts:
장면 시간표와 문구·주제별 색상을 데이터로 정의하는 예시.

주의: 문서와 구현이 항상 완전히 일치하지는 않는다. 예를 들어 KineticCaption은 원본 공통 tokens를 직접 참조하므로 독립 영상에 적용할 때 색상·폰트 주입 구조를 확인해야 한다.

## 작업 순서

1. 메시지·사용 자산·최종 길이를 정한다.
2. 참고 영상의 중요한 구간을 연속 프레임으로 분석하고 장면별 측정표를 작성한다.
3. 참고 장면의 역할을 새 콘텐츠로 대응시킨다. 내용·자산을 그대로 복제하지 않는다.
4. 주요 화면 구도를 먼저 확인한다.
5. 요소 간 연결과 등장·퇴장 동작을 구현한다.
6. 자막·음악·효과음을 같은 시간표에 맞춘다.
7. 전환 구간을 짧게 렌더링하고 연속 프레임으로 검사한다.
8. 전체 MP4를 검토하고 실제 확인한 범위와 미확인 범위를 기록한다.
9. 스타일이 확정된 뒤 사진·문구·숫자를 교체 가능한 데이터로 분리한다.

생성형 영상이 필요한 경우에만 별도 서비스 연결을 검토한다.
정지 이미지로 구도·일관성을 먼저 확인하고 영상 생성 비용을 사용한다.

## 납품 전 체크

- [ ] 참고 영상과 대응 구간을 비교했는가?
- [ ] 글자와 제품 크기를 작은 화면에서도 확인했는가?
- [ ] 장면마다 실제 연출 변화가 있고 정보의 시선 순서가 명확한가?
- [ ] 전환이 갑자기 튀거나 빈 프레임이 생기지 않는가?
- [ ] 화면 밖 잘림·겹침·검은 가장자리·폰트 누락이 없는가?
- [ ] 텍스트가 정착한 뒤 읽을 시간이 있는가?
- [ ] 영상과 음성을 실제로 검토했는가? 불가능했다면 미확인이라고 밝혔는가?
- [ ] 출력 길이·해상도·음성 트랙과 사용 자산 권리를 확인했는가?

대표 화면 몇 장과 파일 생성 성공만으로 완료 판정을 내리지 않는다.
회전·얇은 선의 가장자리가 거칠면 고해상도 렌더 후 축소를 검토한다.
원본 예제의 출력 설정과 패키지 API는 그대로 신뢰하지 말고 설치 버전에서 확인한다.
